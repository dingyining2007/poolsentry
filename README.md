# PoolSentry · 链上池体检（BSC）

**输入一个池地址，回答一个问题：我这笔钱买进再卖出，会损失多少。**

纯链上 RPC 直读，不依赖付费 API，不调第三方「安全评分」。

> 起因：BSC 上 PancakeSwap V2 最近 **200 个新建对**实测（2026-10-26）：
> **83% 根本没有流动性**；在有流动性的 17% 里，**70.6% 让 $10 往返损耗 > 20%**，
> **41.2% 几乎归零（>99.99%）**。但用户在钱包里看到的是「能买也能卖」。
> 复现：`N=200 python3 scripts/verify_68pct_fast.py`
> 免费工具告诉你的「不是蜜罐、税率 0」，和你要问的「这 $10 进去还剩多少」，是两个问题。
> 这个工具只做后一个，并且把每一个数字的口径写出来，让你能自己复现。

---

## 它回答什么问题

| 问题 | 维度 | 口径 |
|---|---|---|
| 我的单子会砸多深？ | D1_depth (25) | **1% 价格冲击所需成交额**（不是 TVL 的 1%，见下） |
| 你能分到的手续费够不够盖 gas？ | D2_fee (25) | 窗口费收 USD / 进出 gas |
| 池子本身成交活不活跃？（能不能赚到手续费） | D3_vol (15) | **日换手率 = 成交额 / TVL / 天** |
| 流动性稳不稳？ | D4_liq (15) | 回撤 / TVL 变化 |
| 有没有人控盘？ | D5_holder (10) | tx.from 去重数 |
| **合约是不是有坑？** | D6_contract (10) | 6 项契约探针，**硬闸** |

**D6 是硬闸**：6 项探针不过，总分直接归零，不参与排序。
理由：合约本身有问题（山寨 factory / 畸形池 / 假 token），其余五个维度算得再漂亮都没有意义。

## 一个容易被搞错的公式（这是本项目最核心的东西）

**「成交额 = TVL 的 1%」≠「价格冲击 1%」，两者差 2 倍。**

从 `x*y=k` 推：把价格从 `p0` 砸到 `0.99*p0`，需要卖出**单边储备的 0.5038%**，
折回 TVL 是 **0.25189%**。

```python
DEPTH_COEF_TVL = (1 / math.sqrt(0.99) - 1) / 2   # 0.00251891
depth_1pct = TVL * 0.00251891
```

不要写 `TVL * 0.01 / 2 = TVL * 0.005` —— 那是「吃进 TVL 的 1%」，**价格实际冲击约 2%**，
会让你的深度估计**乐观一倍**。

这个差值在公开讨论中反复出现。本项目只实现价格冲击口径，并在输出里标注 `definition: price_impact_1pct`。

注意两点：

2. **100 分也是 INSUFFICIENT。** 这是本项目刻意加的一道闸：当 4 个维度缺失时，
   权重归一化后只剩 D1+D6 两个满分项，会算出 100 分并判 ENTER ——
   **那是「缺失被归一化成满分」，必须拦住。** 覆盖率不足过半，一律不许 ENTER。

这条闸是 2026-10-22 实测跑出来才发现的（第一版确实吐了 🟢 ENTER 100.0）。
「没数据不填 0」只是第一步，还必须在判定层拦住它。

## 四条设计铁律（踩过的坑，别重犯）

### 1. 任何指标先过契约探针，不过不许算
池子可能是 V2 / V3 / 克隆盘 / 假池。先用 `token0()` `token1()` `getReserves()` 验身份，
失败了就 `NOT_V2` 直接停，不许硬算。

### 2. 每个数值都带 definition
`depth_1pct` 有价差口径和 TVL 口径两种，差 2 倍。**输出必须标口径**，否则数字没意义。

### 3. 没数据写 `null + reason`，**禁止填 0**
```
"score": null, "reason": "本轮未实现 tx.from 抽样"
```
不是 `"score": 0`。**0 分和"不知道"是两件事**，混在一起排序就废了。

### 4. RPC 返回空 `0x` = 端点伪可用，必须换端点
2026-10-22 实测：多个公开 BSC 端点对 `eth_call` 不报错，直接返回 `"0x"`。
如果代码把它当成「合约不存在」，会得出「池子无效」的错误结论。
→ 本项目把空 `0x` 视为端点故障，自动切换到下一个。

## safety_gate：为什么我们不说「安全」

2026-10-22 多方评审（Agnes / 本机 Agent / 第三方）一致指出一个致命问题：

> 原版把「某个区块、某个 RPC 视角下契约探针通过」等同于「池子安全可评分」。

这是**点快照**，而主流 rug 全部发生在快照之后。因此本项目做了结构性修改。

### 设计上故意没有 `safe` 字段

```json
{
  "verdict": "BLOCKED" | "SNAPSHOT_CLEARED",
  "blockers": [...],
  "warnings": [...],
  "not_covered": [ 8 条必读 ],
  "disclaimer": "点快照，不代表安全"
}
```

`safety_gate` **永远不返回 `"safe": true`**。它只回答「在这一块，未检出以下已知模式」。

### 四条硬拦（有证据才拦）

| code | 判据 | 实现依据 |
|---|---|---|
| `PROXY_UPGRADEABLE` | EIP-1967 实现槽非零 | `eth_getStorageAt` 直读标准槽，比调 `implementation()` 更难伪造 |
| `OWNER_NOT_RENOUNCED` | owner 未 renounce **且** 合约声明了控制函数 | 二者同时成立才拦，见下方「误杀教训」 |
| `SUSPECT_FEE_ON_TRANSFER` | 声明 `feeRate` / `taxFee` / `rebase` | 两方评审一致：误差方向**乐观**，量级 1–10% |
| `DECLARED_CONTROL_CAPS` | 声明黑名单 / pause / 交易开关 | 静态 selector 探测 |

### 一条误杀教训（写进代码防复发）

第一版把 `OWNER_NOT_RENOUNCED` 一律判 BLOCKED，结果 **CAKE（PancakeSwap 自家币）被拦**。

查下去：CAKE 的 `owner()` 指向 MasterChef，但合约里 `pause()` / `blacklist()` /
`setBlackList()` / `tradingEnabled` **全部 revert** —— owner 存在，却没有作恶路径。

→ 改成：**owner 在 + 无控制能力 = `warnings`（告警）；owner 在 + 有能力 = `blockers`（拦截）**。

**理由不是「放宽」，而是「误杀会让闸门被绕过」。** 一个把主流资产全判死的闸门，
用户第一反应是关掉它，那比不拦更危险。

同理，USDT / WBNB / USDC 等蓝筹做了白名单豁免：它们的 owner 不为 0 是常态
（币安桥部署者持有），当风险信号是纯误报。

### 8 条 `not_covered`（每次必打，不许删）

1. 延迟开关（探针跑完后才启用的黑名单 / 卖出限制）
2. 代理升级（本块之后 admin 替换实现）
3. 权限可被改成什么（只读到当前 owner，未读到 owner 的全部能力）
4. 假 token 对（同符号仿冒稳定币，计价基准本身是假的）
5. 单点 RPC 污染（伪造 `eth_call` 可让所有探针在假数据上通过）
6. 真实蜜罐（需买入后卖出实测，涉及私钥，本工具不做）
7. 真实 fee-on-transfer 比例（需转账实测）
8. 持币集中度（本版本未实现 `tx.from` 抽样）

### 为什么不对 V3 估算（评审一致结论）

V3 集中流动性下，深度由 `L` 与 `√P` 决定，不是 `x·y`：

- 相同 TVL，集中流动性可使深度放大**数十到上千倍**
- 价格一旦越过 tick 边界，深度趋近 0，滑点失真可达 **10²–10³ 倍**
- 误差方向**随价格位置翻转**，不是系统性偏差

→ 这不是「系数不准」，是**模型失效**。所以 `pool_probe` 返回 `WRONG_VERSION` 拒绝，
而不是拿 V2 公式套上去给一个看起来合理的数字。
